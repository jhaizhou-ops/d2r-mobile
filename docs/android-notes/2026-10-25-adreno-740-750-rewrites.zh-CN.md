# Adreno 740 / 750：两个 Adreno 着色器改写缺省关闭（2026-10-25）

English: [2026-10-25-adreno-740-750-rewrites.md](2026-10-25-adreno-740-750-rewrites.md)

[#141](https://github.com/jhaizhou-ops/d2r-mobile/issues/141)、[#123](https://github.com/jhaizhou-ops/d2r-mobile/issues/123)、[#137](https://github.com/jhaizhou-ops/d2r-mobile/issues/137)、[#138](https://github.com/jhaizhou-ops/d2r-mobile/issues/138)、[#139](https://github.com/jhaizhou-ops/d2r-mobile/issues/139)、[#142](https://github.com/jhaizhou-ops/d2r-mobile/issues/142) 与 [#143](https://github.com/jhaizhou-ops/d2r-mobile/issues/143) 报的是同一件事：骁龙 8 Gen 2 或 8 Gen 3 的手机上，启动时的声音能听到，约两秒后 App 退出，主菜单还没出来。报告人已确认，这是「完全进不去游戏」，不是进游戏后画面坏了。

## 手机日志说明的事

- **Adreno 740（iQOO 11，驱动 `0x802a403f`）**，见 #141：应用层错误是 `VK_ERROR_DEVICE_LOST`（-4），`dmesg` 里有 `gpu timeout ctx 32` 与 `kgsl ... status 00EF1087`——GPU 页错误，驱动随后丢掉设备。往 `files/dm/` 写 `gfx-quad-derivatives = 0` 与 `gfx-warp32 = 0` 后，同一个导入包在同一台手机上跑了 27,900+ 帧，帧时间 p50 16.63 ms。
- **Adreno 750（Galaxy S24 Ultra）**，见 #123：崩溃前最后一行引擎日志是计算着色器 `098a126f92bf533a` 的 warp32 改写（`rewrites=26`）。
- **Adreno 750（Redmi K70 Pro，8 Gen 3）**，2026-10-25 的崩溃报告：`Abort message: 's.reset_result failed: 2'`。这是引擎的异步命令池重置：`vkWaitForFences` 等槽的栅栏，10 秒后返回 `VK_TIMEOUT`（2），也就是 GPU 一直没做完这次提交，而驱动又没有报设备丢失。所以在这台手机上，失败是 GPU 卡死，而不是设备丢失。单凭这份报告证明不了原因，但「提交永远做不完」正是上面两个改写在高通驱动收下模块后出错的典型表现；槽复用时 App 在记录下来的结果上 abort。

两个改写本来是为 Adreno 730（Redmi K50 Ultra）写的，在 730 和 Adreno 830（一加 13）上都能跑。新一代 7xx 驱动会收下改写后的 SPIR-V，然后在它上面出错或卡死。

## 改动

新增 `xbg_adreno_policy.h`（含 `tests/adreno_policy_test.cpp`）：

| 函数 | 作用 |
|---|---|
| `xbg_adreno_model` | 取 `properties.deviceName` 里 `Adreno` 之后的三位数字（`"Adreno (TM) 740"` → 740） |
| `xbg_adreno_rewrites_fault` | 高通（`vendorID` 0x5143）且型号 740–799 |
| `xbg_adreno_rewrite_option` | 标记文件 > 机型判断 > 环境变量，与其它 gfx 开关同一优先顺序 |

单测只跑 CPU（不碰 Vulkan、不需要 GPU）：`g++ -std=c++17 -Wall -Wextra dm/gfx/vulkan/engine/tests/adreno_policy_test.cpp -o /tmp/adreno_policy_test && /tmp/adreno_policy_test`。

`xbg_game_initialize` 改用它来读 `gfx-quad-derivatives` 与 `gfx-warp32`：在 740/750 上两者缺省为 0，尽管 `jni_android.c` 仍会为需要它们的机型设 `DM_GFX_QUAD_DERIVATIVES=1` 和 `DM_GFX_WARP32=1`。`files/dm/` 里的标记文件仍然优先，做测试时可以单独把任意一个改写重新打开。命中机型时启动日志会多一行说明；原有的 `NVN quad shuffles ...` 与 `NVN 32-lane warps ...` 两行照旧报告结果。

GPU 卡死的日志也变清楚了：池重置线程会记 `NVN command pool reset: the slot's fence did not signal within 10000 ms (GPU hang)`，fatal 信息直接说明是卡死，而不是让崩溃报告里只剩一句 `s.reset_result failed: 2`。

Adreno 730、Adreno 830 和其它厂商的机型不受影响；导入包不用重做，已有的 v2.0.0 导入包配新 APK 就能用。

**为什么不用 #123 的内联。** 那个改动针对的是「着色器编译器拒绝这个模块」；740 是收下模块、之后才在其上出错。#123 里还有一台 Redmi K30 Pro（Adreno 650）的实测：完全内联的模块仍然返回 -13。等两个改写本身修好了，内联可以再回来，但它替代不了这里的机型判断。

## 还需要真机做的事

- 请 8 Gen 2 / 8 Gen 3 的机主确认：当前构建能不能进主菜单和进局，营地、草、水、火焰和邪恶洞穴的战斗画面是否正常。这些机型上 warp32 是关的，而它在 730 上修的正是 32–63 号车道丢失的问题；#141 没看到花屏，但只跑了营地。
- 给 README 的表格补一个营地帧时间。两个改写只改着色器代码，运行期不该多花时间（#141 测到 p50 16.63 ms）。
- 如果还有手机进不去，日志能说明是哪条路：出现 `NVN Adreno 740/750 (device "...")` 说明机型判断命中了；`NVN caps device=` 里是 740/750 却没有这一行，说明没命中。
