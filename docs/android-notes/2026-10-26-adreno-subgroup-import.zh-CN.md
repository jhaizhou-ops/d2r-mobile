# Adreno 750：导入包可选的子组辅助函数内联（2026-10-26）

English: [2026-10-26-adreno-subgroup-import.md](2026-10-26-adreno-subgroup-import.md)

本次新增**显式选择的导入生成路径**，不改变所有 GPU 的缺省行为。依据 [#123](https://github.com/jhaizhou-ops/d2r-mobile/issues/123) 的辅助函数内联建议：Y700 实测在 [#148](https://github.com/jhaizhou-ops/d2r-mobile/pull/148) 两项改写已关闭时，仍能复现启动编译器崩溃。

## 实际观察

设备：Lenovo TB321FU / SM8650 / Adreno (TM) 750，Android 16，Vulkan 1.3.128，驱动 `0x802fa028`（0762.40），系统页大小4096。原实测源码 `445bf05e600dabb735f89d932469396f6a15ea1a`（PR148），PRODUCT `3.3.94012-r44`。

| 导入包，原生APK相同 | 本机结果 |
|---|---|
| 缺省包，运行时quad=0、warp32=0 | 角色选择前3次启动失败，SIG11 / addr=0x48 / exit139 |
| 已有 `DM_VK_INLINE_CS=1`，只处理5个计算模块 | 越过最初计算着色器，随后在像素着色器的同一驱动编译器失败，共2次 |
| 对所有阶段的非入口子组辅助函数内联 | 3次启动进入角色选择；观察到创建角色、营地移动、野外/洞窟渲染、战斗、保存退出和重启读档 |

进程maps将基线PC定位为 `libllvm-qgl.so+0x463ed4`，LR为 `+0x2ec048`。这是本驱动编译器路径的证据，不证明所有骁龙启动失败都是同一原因。识别非入口子组辅助函数并提出内联处理的贡献来自#123报告者。

首个成功进程至少存活31分钟，其中营地内观察至少18分钟。鲜血荒地和邪恶洞窟使用项目临时开关 `DM_TEST_GOTO_LEVEL=100:2;2000:8` 到达，不是正常旅行。战斗达到1级经验21%；无人操作时测试角色随后死亡，继续回营地、取回装备并保存。第三次启动前已移除临时env，正常读取存档。从未清除应用数据。

## 修改

生成导入包时设置 `DM_VK_INLINE_SUBGROUP=1`。若模块的非入口函数含 `OpGroupNonUniform*`，导出器执行：

```
spirv-opt --target-env=vulkan1.1 --merge-return --inline-entry-points-exhaustive --eliminate-dead-functions
```

处理在绑定号/能力处理后、最终验证和反射前执行。优化器失败或仍有子组辅助函数时构建失败。原有Vulkan 1.1验证器仍逐模块检查。实测包改变187个游戏模块：182个像素和5个计算模块；不含这种辅助函数的模块保持原样。原生APK、描述符和XGS布局不变。

新开关优先于已有的仅计算内联开关。两个开关都不设，或只设 `DM_VK_INLINE_CS=1` 时，保持原行为。使用新模式时，`pack_info.txt` 记录 `SHADER_SUBGROUP_INLINE=1`。

## 只用于两项运行时改写关闭的组合

像素quad改写器匹配翻译器原有辅助函数调用形态；离线内联可能消除该形态，因此**需要开启quad/warp改写的设备不要使用此包**。PR148在高通Adreno 740–799缺省关闭两项，但显式标记文件仍优先。以设备日志确认两项均为0。Adreno740尚未实测本模式；730、735、830、其它厂商或驱动版本也未验证。

从与已装APK兼容的源码执行：

```sh
DM_VK_INLINE_SUBGROUP=1 python3 dm/tools/d2rm_android.py <Update目录> <新输出目录>
```

通过应用正常流程导入生成的 `android` 文件夹。里面有自己的游戏内容，必须保持私有。不引入打包器现有SPIRV-Tools以外的依赖。本次修改不附APK或游戏包。

当前main另有 `81e692d` 的计算管线跳过/失败保护（[#153](https://github.com/jhaizhou-ops/d2r-mobile/issues/153)）。本次保留该保护和其中Adreno750跳过策略，不重新启用被跳过的流体着色器。上述Y700原生观察使用更早的PR148 APK，**不能据此断言最新缺省APK仍失败**。本模式为像素辅助函数失败提供可复现的额外绕过方案，并能生成已经实测的着色器形态。

## 检查与边界

- 修改前后均通过源码字面量与i18n检查。
- `python3 dm/gfx/tools/tests/test_dmsh_vk_inline.py`：手写计算/片元SPIR-V，实际运行优化和验证，覆盖无需处理时字节保留和失败停止；需要与打包器相同的 `SPIRV_OPT` / `SPIRV_VAL`，无需游戏文件。
- 真实全包重新生成与实测产物对比结果记录在PR中。
- 原实机验证在正常保存退出后归档旧管线缓存，以验证首次编译；存档保留。生成着色器、截图、游戏文件和原始设备日志均保持私有。
- 长期游玩、全流程、主观音频、参考画面一致性、其它GPU/驱动、实体16KB页设备均未验证。APK/ELF静态16KB对齐另计。
