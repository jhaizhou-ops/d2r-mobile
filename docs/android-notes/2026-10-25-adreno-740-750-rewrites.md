# Adreno 740 / 750: the two Adreno shader rewrites default off (2026-10-25)

中文：[2026-10-25-adreno-740-750-rewrites.zh-CN.md](2026-10-25-adreno-740-750-rewrites.zh-CN.md)

Issues [#141](https://github.com/jhaizhou-ops/d2r-mobile/issues/141), [#123](https://github.com/jhaizhou-ops/d2r-mobile/issues/123), [#137](https://github.com/jhaizhou-ops/d2r-mobile/issues/137), [#138](https://github.com/jhaizhou-ops/d2r-mobile/issues/138), [#139](https://github.com/jhaizhou-ops/d2r-mobile/issues/139), [#142](https://github.com/jhaizhou-ops/d2r-mobile/issues/142) and [#143](https://github.com/jhaizhou-ops/d2r-mobile/issues/143) all report the same shape on a Snapdragon 8 Gen 2 or 8 Gen 3 phone: the startup audio plays, the app dies about two seconds later, before the main menu. The reporter has confirmed that this is the "cannot get into the game at all" case, not a broken picture after loading.

## What the phone logs show

- **Adreno 740 (iQOO 11, driver `0x802a403f`)**, #141: the app-level error is `VK_ERROR_DEVICE_LOST` (-4), and `dmesg` has `gpu timeout ctx 32` and `kgsl ... status 00EF1087` — a GPU page fault, after which the driver drops the device. With `gfx-quad-derivatives = 0` and `gfx-warp32 = 0` in `files/dm/` the same import pack ran 27,900+ frames at a 16.63 ms p50 on the same phone.
- **Adreno 750 (Galaxy S24 Ultra)**, #123: the last engine line before the crash is the warp32 rewrite of compute shader `098a126f92bf533a` (`rewrites=26`).
- **Adreno 750 (Redmi K70 Pro, 8 Gen 3)**, the crash report on 2026-10-25: `Abort message: 's.reset_result failed: 2'`. That is the engine's asynchronous command pool reset: `vkWaitForFences` on the slot's fence returned `VK_TIMEOUT` (2) after 10 seconds, i.e. the GPU never finished the submission and the driver did not report the device lost. So on this phone the failure is a GPU hang rather than a device-lost error. The report alone does not prove the cause, but a submission that never finishes is what the rewrites above produce when the driver accepts the module and then faults; the slot reuse is where the recorded result aborts the app.

Both rewrites were written for the Adreno 730 (Redmi K50 Ultra) and run there and on the Adreno 830 (OnePlus 13). The newer 7xx drivers accept the rewritten SPIR-V and then fault or hang on it.

## Change

`xbg_adreno_policy.h` (new, with `tests/adreno_policy_test.cpp`):

| Function | Purpose |
|---|---|
| `xbg_adreno_model` | the three digits after `Adreno` in `properties.deviceName` (`"Adreno (TM) 740"` → 740) |
| `xbg_adreno_rewrites_fault` | Qualcomm (`vendorID` 0x5143) and model 740–799 |
| `xbg_adreno_rewrite_option` | marker file > device family > environment, the same precedence as the other gfx switches |

The test is CPU-only (no Vulkan, no GPU): `g++ -std=c++17 -Wall -Wextra dm/gfx/vulkan/engine/tests/adreno_policy_test.cpp -o /tmp/adreno_policy_test && /tmp/adreno_policy_test`.

`xbg_game_initialize` now reads `gfx-quad-derivatives` and `gfx-warp32` through it, so on a 740/750 both default to 0 even though `jni_android.c` still sets `DM_GFX_QUAD_DERIVATIVES=1` and `DM_GFX_WARP32=1` for the devices that want them. A marker file in `files/dm/` still wins, so either rewrite can be forced back on for a test. Startup logs one line naming the gate when it fires, and the two existing `NVN quad shuffles ...` / `NVN 32-lane warps ...` lines report the result.

A hung GPU also reads better now: the pool-reset worker logs `NVN command pool reset: the slot's fence did not signal within 10000 ms (GPU hang)` and the fatal message names the hang, instead of the crash report showing only `s.reset_result failed: 2`.

Nothing changes for Adreno 730, Adreno 830 or other vendors, and the import pack does not change: an existing v2.0.0 pack works with the new APK.

**Why not the inlining from #123.** That change targets a shader compiler that rejects the module; the 740 accepts the module and faults on it later. #123 also has a Redmi K30 Pro (Adreno 650) test where a fully inlined module still fails with -13. Inlining can come back if the rewrites themselves are repaired, but it does not replace this gate.

## What still needs a phone

- An 8 Gen 2 / 8 Gen 3 owner to confirm the current build reaches the main menu and a game, and that the camp, the grass, water and fire effects and the Den of Evil fight look right. Warp32 is off there, and its lost-lane bug is what the rewrite fixed on the 730; #141 saw no artifacts, but only ran the camp.
- A camp frame time for the table in the README. The rewrites only change shader code, so the run-time cost should be nil (#141 measured 16.63 ms p50).
- If a phone still stops, the log tells which way it went: `NVN Adreno 740/750 (device "...")` means the gate fired, and no such line with a 740/750 in `NVN caps device=` means the gate did not.
