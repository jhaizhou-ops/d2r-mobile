## 0. 一句话结论

Android 的**交互算法已经是 iOS 同一套**（`dm_touch_controls.c` 共享：摇杆/瞄准/腰带/双击顺序
全一致）；差的主要是**视觉**——按钮的样式、摇杆的样子、淡出/按压反馈。这一轮把视觉层按 iOS
的调色板与画法重做（见 §2），并在真机上逐项核对（见 §4）。

## 2. 这一轮改了什么（代码）

1. **`dm/android/src/org/d2r/binaryprobe/TouchControlsView.java`**（重写绘制层）：
   - 调色板换成 iOS 的：底 `#16110c`、铜环 `#997845`、内圈暗环 `#1f170d`、羊皮纸文字 `#d9c9a6`、
     星纹 `#c8a460`（数值都从 DmTouchOverlay.m 抄的）。
   - 画法照抄：双环（外亮内暗）、闲时 ×0.6 淡出（`DM_SKILL_IDLE_ALPHA`）、按住变实；
     腰带格淡环 + 数字 1–4；摇杆=淡环 + 星纹帽 + 转向弧。
2. **`GameActivity.java`**：模式切换钮与动作按钮（确认/返回/开始/方向）统一改成"暗底 + 铜边 +
   圆角"（新 `buttonBackground()`），文字色同触摸层。
3. **`DESIGN.md`**：触摸层一节改成新 token 的描述（这份是 Android 外观的"户口本"）。
4. 隔离规矩收尾：`sync_surface_audit.sh` 复查通过——动上游文件数 **35 → 35**（上一轮加的
   `.gitignore` 改动已撤掉，IDE 忽略改放本机 `.git/info/exclude`，不进版本库）。

## 3. 剩下的大项（都记下来，别丢）

1. **底栏 v4 + 手柄提示消除**（一处修两样）：iOS 这两样都靠"生成 overlay 数据 + 挂到 RomFS
   上"。Android 的 romfs 是打包镜像（`romfs_image.c`，无 overlay 层）——要做的话是三步：
   ① 给 Android 的文件层加"先查 overlay 目录、再查镜像"（照 hle_fs.c 的 DM_ROMFS_OVERLAY 语义）；
   ② 跑 iOS 那两个生成器（`gen_assets.py` / `gen_romfs_overlay.py`，需要玩家自己的 RomFS 源文件）；
   ③ 生成物推到设备或打进包。收益：底栏按键字母变透明、"按 A 使用"变"双击使用"、金色 X 等
   16 项文案/图标差异（详见 `docs/android/ui-parity/analysis.zh-CN.md` §4.2）。
2. **面板开合自动切模式**：需要"当前场景/面板栈"读数。iOS 用 `dm_hud_stack_msg()` +
   `dm_tc_panel_mode()`（共享代码现成），但 Android 这条路要有原始游戏场景观察桥（91738 未映射，
   见 `touch_controls_android.c` 顶部注释）——做了这个，模式切换钮就可以退休。
3. **掉落震动**：`dm_drophaptic.c` 判定是共享的，Android 只缺输出端（Java Vibrator 三档）。
4. **技能图标上钮**（有图标画图标、无图标画十字）：需要 native art 桥（技能绑定读数），同 §3-2
   的前置条件。

## 5. 附录：本地预演的数值自检

隐藏细则（与 iOS 数值的对应）：
- 动作钮环宽 `max(1.5, r×0.075)`（iOS `MAX(1.5,t->r*0.075)`）；内环半径 `r−lw×1.3`、宽 `lw/2`。
- 摇杆帽直径 = 底盘半径 × 0.383（iOS 46k/120k＝0.383）；星纹尖端 = 帽半径 × 0.45
  （素材 27px/60px）；弧半径 `r+3k`、宽 `2k`、张角 ±30°。
- 文字：主技能 `max(11, r×0.30)`、技能 `max(11, r×0.40)`、功能钮 `max(8, r×0.38/0.40)`（iOS 为
  图片标签，高度约 r×0.30–0.36；此处按可读性取同量级）。
