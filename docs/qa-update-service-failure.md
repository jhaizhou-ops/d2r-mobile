# Update service failure (#79)

Public base: 9393b00. User build10172332 logs three HTTP530 responses from its configured manifest URL. Independent requests returned Cloudflare1033; the endpoint still failed during this investigation. Public source contains no deployment/Tunnel configuration, and this patch does not repair or claim access to that server. Only its operator can restore the connector/DNS/origin configuration. Do not replace the configured publishing endpoint or invent an install URL to mask the outage.

Client changes:
- Distinguish HTTP5xx service failure (kind3) from data permission denial (kind1) and other failures (kind2). Display a localized service-unavailable/retry-later line rather than direct users to the same failed host in a browser. Existing offers remain preserved, retries remain three, and a later successful check clears the notice as before.
- Extract the production Foundation response policy. A failed HTTP response or invalid manifest can no longer supply render_safe. Previously JSON error bodies and invalid partial manifests were inspected even when the request/manifest was rejected, allowing an error payload to change renderer mode. Valid complete manifests keep their existing renderer fallback behavior and installation URL contract.

The initial actual-policy fixture failed7/22 checks before the fixes. Final expanded fixture passes36/36 normally and under UBSan, covering530/500/503, valid-looking error JSON, invalid manifest,404/304/429, valid manifests with/without an enabled renderer fallback, oversized data and a transport error. The production Objective-C translation unit passes iPhoneOS SDK syntax checking (arm64 iOS16 target); host C syntax, generated i18n/literal, native-write, mode and diff checks pass. Tests use authored responses, no game content or live installation.

No full game package build, native character-select rendering screenshot or iPad acceptance was possible without original game files. This PR is draft until the changed text is checked in both languages and normal/urgent offers, permission/offline states and later recovery are verified on device. For native fixtures use DM_TEST_UPDATE_URL pointing to a maintained test endpoint returning530/503, then200 with a valid manifest; test attempts1/2 produce no failure notice and attempt3 shows service failure. Confirm a JSON-shaped500/invalid manifest cannot switch renderer, and an approved complete200 manifest still can. Do not invoke install URLs during automated checks.

Server acceptance is separate: owner restores a healthy Tunnel, externally proves200+valid manifest, checks its installation entry separately, then rechecks the same iPad. A green client test or merged PR is not proof that the update service is available.
