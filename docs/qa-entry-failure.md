This patch is diagnostic only: it does not change the15000ms warm-up limit, guest clock, packets, saves or error handling. At the native UI observation gate it records load start/end and the first fatal-panel message before subscribers run. Each error episode coalesces repeated opens, and at most four fatal snapshots per process include a frame-pointer chain (24frames maximum, each pair read with vm_read_overwrite; stop on failed read, misalignment or non-increasing pointers). This is the observer's chain, not guaranteed to reach the originating error or contain its code. Synthetic host panel-heal messages are not sampled.

Event numbers:1 load-open,2 load-close/unload,3 first-fatal snapshot,4 fatal-close with repeat count. Attempts count load-open messages, not uniquely identified game instances; map loads also count. Tick0 may mean no active server state. The optional host callback around the existing warm wait records wall/guest-clock deltas and tick/frame numbers at both ends. Standalone graphics tests leave the callback null.
