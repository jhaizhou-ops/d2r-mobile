# 更新服务故障（#79）

公开基线9393b00。用户构建10172332连续三次请求配置的版本地址收到HTTP530；独立请求返回Cloudflare1033，调查中接口仍失败。公开源码没有部署/Tunnel配置，本补丁不修复该服务器，也不声称拥有管理权限；须服务拥有者恢复连接器/DNS/源站配置。不能换成不明发布端点或编造安装链接掩盖故障。

客户端改动：
- HTTP5xx归为服务故障（kind3），与数据许可被拒（kind1）、其他失败（kind2）分开。显示中英“服务暂不可用/稍后重试”，不再引导浏览器访问同一故障站。已有更新提示继续保留，仍重试三次，后续成功照旧清除失败状态。
- 抽出生产Foundation响应策略。HTTP失败或清单无效时，不能提供render_safe。原来即使请求/清单已拒绝，仍检查JSON错误页或无效的部分清单，错误载荷可改变绘制模式。完整有效清单保留既有绘制回退与安装URL契约。

最初实际策略夹具修改前22项中7项失败；最终扩展36/36及UBSan通过，覆盖530/500/503、像有效清单的错误JSON、无效清单、404/304/429、有效清单绘制开关开/关、超长数据与网络传输错误。生产Objective-C单元通过iPhoneOS SDK语法检查（arm64 iOS16目标）；宿主C语法、中英表生成/字面量、控件写入、模式和diff检查通过。测试使用自造响应，不含游戏内容、不执行真实安装。

缺原版游戏文件，未做完整游戏包构建、原生选角页修改后截图或iPad验收。草稿PR须待中英提示及普通/紧急更新提示、权限/离线状态、后续恢复通过真机验证。原生夹具可用DM_TEST_UPDATE_URL指向维护方测试端点，先返回530/503再返回有效200清单；确认第1/2次不显示失败、第3次显示服务故障。JSON形状的500或无效清单不能切绘制，有效且获准的完整200清单仍可。自动检查不打开安装URL。

服务端独立验收：维护方恢复健康Tunnel，外部证明HTTP200和有效版本清单，单独核对安装入口，再用同一iPad检查。客户端测试通过或PR合入不能证明更新服务已经恢复。
