# dm/host：宿主文件索引

可选的 [Mac PC 输入配置](../../docs/mac-pc-input.zh-CN.md)：集成前提和专项测试。

English: [README.md](README.md)

宿主做两件事：装载改写后的游戏程序、提供它调用的平台服务；在原版之上加的功能和触摸适配也在这个目录里。整体怎么工作见 [dm/README.zh-CN.md](../README.zh-CN.md)。

文件名的前缀就是分工：

- 没有前缀的（`main.c`、`loader.c`、`entry.S`……）与 `hle*.c`：装载、系统调用、系统服务、前端与诊断。这部分在 [dm/README.zh-CN.md](../README.zh-CN.md) 的「host/ 各文件」一节已逐个列出，本页不重复，只补那里没列的。
- `dm_*.c`：在原版之上加的功能和触摸适配。那一节只举了几个例子，本页按职责列全。

每个文件开头的注释说明它做什么、依据是什么；功能文件里的地址都是 3.3.94012 原映像的偏移。

## 基础部分里上面那一节没列的

| 文件 | 管什么 |
|---|---|
| `Makefile` | 编出 Mac 宿主 `dmhost`。`hle_*.c` 与图形层的源文件按通配纳入，新增文件不用改它；缺的三份表（`dm_vault_tab.h`、`dm_hud_exp.h`、`dm_bright_levels.inc`）从你的游戏文件现生成，不进仓库 |
| `hle_target.c` | 触屏点按时自动选怪的先后：首领、精英、普通。接在原版手柄选目标的比较函数上，原版的资格、射程、视线检查照旧 |
| `hle_private_aim.c` | 拖动技能键瞄准：把右摇杆在屏幕上的方向换算成游戏世界里的方向 |
| `touch_mac.c`、`touch_mac.h` | Mac 宿主上的触摸前端：按触点脚本（`DM_TOUCH_SCRIPT`）逐拍送触点，[dm/verify](../verify/README.zh-CN.md) 的触摸功能用例靠它跑 |
| `romfs_validate.h` | `romfs_validate.c` 的接口：核对资源档案在不在、大小对不对，并给出给玩家看的缺失清单 |
| `stash_seed.h` | 第一次生成共享仓库时用的预置内容。公开仓库不带这个文件（它是游戏生成的一份存档的字节）：不在就不预置 |
| `dm_derived_rt.h` | 只在不含游戏内容的「壳」里用：由游戏文件生成的几张表不编进代码，运行时从安装包里读，见 [docs/NO_XCODE.zh-CN.md](../../docs/NO_XCODE.zh-CN.md) |

另外，`diag.c` 除了诊断，还是每个服务端拍的入口：`dm_vault.c`、`dm_pages.c` 等要在服务端拍里做的事由它调用。

## 游戏内功能（`dm_*`）

### 触摸与界面交互

| 文件 | 管什么 |
|---|---|
| `dm_cursor.c`、`dm_cursor.h` | 触摸落到游戏界面的那一层：把触点变成原版光标位置与确认键，把点击作为界面消息发给原版控件，判定拖放的落点。各功能的每帧处理也在这里按触屏 / 手柄模式调度 |
| `dm_cursor_item.c`、`dm_cursor_item.h` | 光标当前指着哪件物品，按游戏自己的悬停对象取，不按格子坐标反算 |
| `dm_world.c`、`dm_world.h` | 点游戏世界里的目标就是与它交互：点物品名拾取，点 NPC、物件、出口走过去再交互。复用游戏自己的点击入口 |
| `dm_actions.c`、`dm_actions.h` | 「先选中、再确认」的入口：商人买卖、属性与技能加点、数量框设值。全部走游戏手柄版自己的路径 |
| `dm_textinput.c` | 界面文本框（金币数量、编年史搜索等）接系统键盘 |
| `dm_textbox.c`、`dm_textbox_core.c`、`dm_textbox_core.h` | 让普通文字框正确显示物品注释里的颜色码；`_core` 是不碰游戏内存的纯逻辑，单测直接测它 |

### 手柄与两种模式

| 文件 | 管什么 |
|---|---|
| `dm_padmode.c` | 手柄 / 触屏两套界面布局：连上手柄回到原版手柄界面，碰屏幕回触屏界面，切换不重启 |
| `dm_modetx.h` | 模式切换的事务：冻结输入、旧一侧收手、游戏重建界面、新一侧就位、放开输入。纯状态机 |
| `dm_mode_items.h` | 只在触屏或只在手柄模式下做事的行为的登记表；新加按模式分的行为在这里登记一行 |
| `dm_padmap.h` | 实体手柄四个面键对应到游戏键：按键帽上印的字母对应 |

### 屏幕与画面

| 文件 | 管什么 |
|---|---|
| `dm_uiscreen.c`、`dm_uiscreen.h` | 比 16:9 窄的屏幕（iPad）上，界面按 16:9 摆、3D 画面仍铺满整屏 |
| `dm_bright.c` | 「3D 画面加亮」的动态曝光：按所在关卡的类型决定加亮多少 |
| `dm_hud.c`、`dm_hud.h` | 底部界面上的数字（等级、经验百分比、难度），以及难度档位（1–8）的请求 |

### 文字与语言

| 文件 | 管什么 |
|---|---|
| `dm_i18n.c`、`dm_i18n.h` | 我们加的界面文字按键取串，语言跟游戏的语言设置走 |
| `dm_i18n_tab.h` | 由中英表生成的编译期表。生成文件，不要手改，见 [dm/i18n/README.zh-CN.md](../i18n/README.zh-CN.md) |
| `dm_update.c` | 选角页的构建号与新版本提示 |
| `dm_namegen.c` | 起名页留空时随机取名：按音节拼，避开已有的角色名 |

### 终局玩法

| 文件 | 管什么 |
|---|---|
| `dm_rift.c`、`dm_rift.h` | 秘境：进门、抽图、进度、守护者、计时与层数结算 |
| `dm_rift_ui.c` | 秘境面板，用原版控件搭 |
| `dm_doorspot.h` | 秘境结算处两扇门落在哪：保证落在玩家走得到的格上。纯算法 |
| `dm_bossrush.c`、`dm_bossrush.h` | 首领连战 |
| `dm_elysium.c`、`dm_elysium.h` | 极乐世界模式：建角时勾选的按角色开关，进局时改内存里的数据表，退局写回原值 |
| `dm_kills.c` | 刷怪积分牌：按角色、按难度记首领的击杀次数、首杀时刻与最快用时 |

### 仓库与物品

| 文件 | 管什么 |
|---|---|
| `dm_vault.c` | 编年史仓库的服务端一半：已鉴定的暗金与套装的存入、取出 |
| `dm_vault_ui.c` | 编年史仓库的界面：储藏箱的第六个页签 |
| `dm_pages.c` | 个人仓库第 2–5 页：另外几页的物品存在角色目录的侧文件里，翻页在服务端拍里做 |

|---|---|

## tests/

宿主的单元测试，一条命令：

```
make -C dm/host/tests run
```

需要游戏文件与 `./setup.sh` 备好的工作区。`t_*.c` 是各模块的单测；一起跑的还有四条只读源码的检查：不许写原版界面控件（`native_write_scan.py`）、触屏 / 手柄模式的登记（`mode_scan.py`）、中英表与生成头文件一致（`dm/ios/tools/dm_i18n.py --check`）、字面量闸门（`dm/i18n/scan_literals.py`）；以及两条对着原版程序映像的核对（`movie_cut.py`、`oe_notify.py`）。

目录里另有几个不在这条命令里的独立脚本（`run_rule.py`、`run_manifest.py`、`move_codec.py`、`client_sta_gate.py`、`server42_rule.py`、`server_walk_request.py`），各自的用途与局限写在文件头。
